# OPD Predictive Analytics and Scenario-Testing System (starter prototype)

OPD pathway modelled: registration, triage, consultation, laboratory, radiology, pharmacy.

A working web application matching the architecture in Chapter 3:
data layer -> Python analytics core (ML + SimPy simulation) -> web dashboard with login and roles.

## 1. Run it
```bash
python -m venv venv
venv\Scripts\activate          # Windows   (Mac/Linux: source venv/bin/activate)
pip install -r requirements.txt
streamlit run app.py
```
Open http://localhost:8501. Demo logins (change them in auth.py before real use):
admin / ChangeMe-Admin1, manager / ChangeMe-Manager1, supervisor / ChangeMe-Super1.

It starts in DEMO MODE with synthetic data generated by the simulator. Synthetic data is for
testing the software only. Never report it as a research result.

## 3. Practise with the synthetic sample, then switch to real data (preprocessing)
`sample_data/SYNTHETIC_sample_lhims_export.csv` imitates a raw hospital export, including fake personal
identifiers, duplicates, missing times, out-of-order times and impossible durations. It is SYNTHETIC: use it
only to test the pipeline and the app. Never report it as real data or as a result.
```bash
python preprocess.py sample_data/SYNTHETIC_sample_lhims_export.csv
python -m streamlit run app.py
```
`preprocess.py` anonymises, cleans, imputes (MICE-style, fitted on training days only), builds the waiting times and
queue lengths, and writes `data/visits.csv` for the app, plus `data/table_4_1_data_quality.csv` and
`data/table_4_2_descriptive_stats.csv` for Chapter 4. The app shows a red warning while a synthetic file is loaded.
The raw export needs `lab_start`/`lab_end` and `radiology_start`/`radiology_end` columns (leave them empty for patients without those investigations; if the hospital keeps them in separate laboratory or radiology systems, ask for those extracts too and join them on the visit ID).
With the real extract: open `preprocess.py`, edit `COLUMN_MAP` and the settings at the top so the column names and
opening hours match the hospital's export, run `python preprocess.py real_export.csv`, and the warning disappears.
To go back to demo mode, delete everything inside the `data` folder.
(`make_sample_export.py` regenerates the synthetic sample.)

## 3b. Required columns of data/visits.csv (created by preprocess.py)
Save the de-identified extract as `data/visits.csv`; the app then leaves demo mode automatically.
Convert times to minutes since 07:00 of each day. Required columns:
`day, dow, hour, arrival,`
`reg_arr, reg_q, reg_start, reg_end, triage_arr, triage_q, triage_start, triage_end,`
`consult_arr, consult_q, consult_start, consult_end, lab_* and rad_* (laboratory and radiology; empty for patients who do not use them), pharm_arr, pharm_start, pharm_end, depart,`
plus `reg_wait, triage_wait, consult_wait, pharm_wait, total_time` (start minus arr; depart minus arrival).
`*_q` is the number of people already queueing at that stage when the patient joined.
Compute it from timestamps in a preprocessing script (this is your ETL step).

## 3c. Models, statistical tests and thesis tables (Objective 3)
```bash
python run_experiments.py
```
Trains and tunes Linear Regression, Random Forest, XGBoost and LightGBM (time-series cross-validation), compares them
with the hourly-average baseline on a chronological 70/15/15 split, and saves to `results/`: Table 4.3 (test
performance), Table 4.4 (GREEN/AMBER/RED classification), the Diebold-Mariano and Wilcoxon tests of H0_1 with Holm
correction, forecasts 1-3 hours ahead, SHAP importance, and two figures. The same results appear in the app under
"2. Predictive bottleneck alerts" (it takes about a minute to load the first time).
LSTM: optional because PyTorch is a large download. Run `pip install -r requirements-lstm.txt` to enable it. The LSTM
code could not be run by the author of this package, so check its output and report any error.
Congestion thresholds (AMBER_MIN, RED_MIN) are at the top of `model.py`: confirm them with hospital management.

## 3d. Usability survey (Objective 6)
Type each participant's answers into `survey_template.csv` (save as `survey_responses.csv`), then run
`python analyse_survey.py survey_responses.csv` to get Tables 4.8 and 4.9, the SUS score, Cronbach's alpha and the
Wilcoxon test of H0_2. The questionnaire itself is in `Research_Instruments_and_Ethics.docx`.

## 4. Replace the demo assumptions with your hospital's values (sim.py -> DEFAULT)
Staff numbers, hourly arrival rates, mean service times and lab referral probability should be
fitted from your data (Section 3.8 of the thesis), then validated against observed waits
(Table 4.6) before you trust any scenario result.
